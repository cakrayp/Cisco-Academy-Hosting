Implementasi VLAN

Memecahkan masalah VLAN dan Trunks

Tautan utama biasanya dikonfigurasikan secara statis denganbagasi mode switchportmemerintah. Port trunk switch Cisco Catalyst menggunakan DTP untuk menegosiasikan status tautan. Ketika port pada link trunk dikonfigurasi dengan mode trunk yang tidak kompatibel dengan port trunk tetangga, link trunk gagal terbentuk di antara kedua switch.

Dalam skenario yang diilustrasikan pada Gambar 1, PC4 tidak dapat terhubung ke server web internal. Topologi menunjukkan konfigurasi yang valid. Mengapa ada masalah?

Periksa status port trunk pada saklar S1 menggunakantampilkan antarmuka bagasimemerintah. Output yang ditunjukkan pada Gambar 2 menunjukkan bahwa antarmuka Fa0/3 pada saklar S1 saat ini bukan merupakan link trunk. Memeriksa antarmuka F0/3 menunjukkan bahwa port switch sebenarnya dalam mode otomatis dinamis. Pemeriksaan trunk pada saklar S3 menunjukkan bahwa tidak ada port trunk yang aktif. Pemeriksaan lebih lanjut mengungkapkan bahwa antarmuka Fa0/3 juga dalam mode otomatis dinamis. Ini menjelaskan mengapa bagasinya turun.

Untuk mengatasi masalah ini, konfigurasi ulang mode trunk port F0/3 pada sakelar S1 dan S3, seperti yang ditunjukkan pada Gambar 3. Setelah konfigurasi berubah, output daritampilkan antarmukaperintah menunjukkan bahwa port pada saklar S1 sekarang dalam mode trunking. Output dari PC4 menunjukkan bahwa ia telah mendapatkan kembali konektivitas ke server Web/TFTP yang ditemukan di alamat IP 172.17.10.30.
