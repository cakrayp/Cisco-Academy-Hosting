Protokol Trunking Dinamis

Antarmuka trunk Ethernet mendukung mode trunking yang berbeda. Sebuah antarmuka dapat diatur ke trunking atau nontrunking, atau untuk menegosiasikan trunking dengan antarmuka tetangga. Negosiasi trunk dikelola oleh Dynamic Trunking Protocol (DTP), yang beroperasi hanya pada basis point-to-point, antar perangkat jaringan.

DTP adalah protokol milik Cisco yang diaktifkan secara otomatis pada switch Catalyst 2960 dan Catalyst 3560 Series. Switch dari vendor lain tidak mendukung DTP. DTP mengelola negosiasi trunk hanya jika port pada switch tetangga dikonfigurasi dalam mode trunk yang mendukung DTP.

Peringatan: Beberapa perangkat internetworking mungkin meneruskan frame DTP secara tidak benar, sehingga dapat menyebabkan kesalahan konfigurasi. Untuk menghindari hal ini, matikan DTP pada antarmuka pada switch Cisco yang terhubung ke perangkat yang tidak mendukung DTP.

Konfigurasi DTP default untuk switch Cisco Catalyst 2960 dan 3560 adalah otomatis dinamis seperti yang ditunjukkan pada Gambar 1 pada antarmuka F0/3 switch S1 dan S3.

Untuk mengaktifkan trunking dari switch Cisco ke perangkat yang tidak mendukung DTP, gunakanbagasi mode switchportDanswitchport tidak bernegosiasiperintah mode konfigurasi antarmuka. Hal ini menyebabkan antarmuka menjadi trunk, tetapi tidak menghasilkan frame DTP.

Pada Gambar 2, hubungan antara switch S1 dan S2 menjadi trunk karena port F0/1 pada switch S1 dan S2 dikonfigurasi untuk mengabaikan semua iklan DTP, dan masuk dan tetap berada dalam mode port trunk. Port F0/3 pada sakelar S1 dan S3 diatur ke otomatis dinamis, sehingga negosiasi menghasilkan status mode akses. Hal ini menciptakan link trunk tidak aktif. Saat mengonfigurasi port untuk berada dalam mode trunk, tidak ada ambiguitas tentang status trunk berada; itu selalu menyala. Dengan konfigurasi ini, mudah untuk mengingat di negara bagian mana port utama berada; jika port seharusnya menjadi trunk, mode diatur ke trunk.
