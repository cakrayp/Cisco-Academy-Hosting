Memecahkan Masalah Rute Statis dan Default

Pemrosesan Paket dengan Rute Statis

Contoh berikut menjelaskan proses penerusan paket dengan rute statis.

Pada gambar, klik tombol Play untuk melihat animasi dimana PC1 mengirimkan paket ke PC3:

1. Paket tiba di antarmuka GigabitEthernet 0/0 R1.

2. R1 tidak memiliki rute khusus menuju jaringan tujuan, 192.168.2.0/24; oleh karena itu, R1 menggunakan rute statis default.

3. R1 merangkum paket dalam frame baru. Karena link ke R2 adalah link point-to-point, R1 menambahkan alamat "semua 1" untuk alamat tujuan Layer 2.

4. Frame diteruskan keluar dari antarmuka Serial 0/0/0. Paket tiba pada antarmuka Serial 0/0/0 di R2.

5. R2 mendeenkapsulasi frame dan mencari rute ke tujuan. R2 memiliki rute statis ke 192.168.2.0/24 dari antarmuka Serial 0/0/1.

6. R2 merangkum paket dalam frame baru. Karena link ke R3 adalah link point-to-point, R2 menambahkan alamat "semua 1" untuk alamat tujuan Layer 2.

7. Frame diteruskan keluar dari antarmuka Serial 0/0/1. Paket tiba pada antarmuka Serial 0/0/1 di R3.

8. R3 mendeenkapsulasi frame dan mencari rute ke tujuan. R3 memiliki rute yang terhubung ke 192.168.2.0/24 dari antarmuka GigabitEthernet 0/0.

9. R3 mencari entri tabel ARP untuk 192.168.2.10 untuk menemukan alamat Kontrol Akses Media (MAC) Lapisan 2 untuk PC3. Jika tidak ada entri, R3 mengirimkan permintaan Address Resolusi Protocol (ARP) dari antarmuka GigabitEthernet 0/0, dan PC3 merespons dengan balasan ARP, yang mencakup alamat MAC PC3.

10. R3 merangkum paket dalam bingkai baru dengan alamat MAC antarmuka GigabitEthernet 0/0 sebagai alamat Layer 2 sumber dan alamat MAC PC3 sebagai alamat MAC tujuan.

11. Frame diteruskan keluar dari antarmuka GigabitEthernet 0/0. Paket tiba di antarmuka kartu antarmuka jaringan (NIC) PC3.
