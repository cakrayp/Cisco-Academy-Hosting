Konfigurasi NAT

Mengonfigurasi Terjemahan Alamat Port (PAT)

Proses kelebihan NAT adalah sama, baik kumpulan alamat digunakan atau alamat tunggal digunakan. Melanjutkan contoh PAT sebelumnya, dengan menggunakan satu alamat IPv4 publik, PC1 ingin berkomunikasi dengan server web, Svr1. Pada saat yang sama klien lain, PC2, ingin membuat sesi serupa dengan server web Svr2. Baik PC1 dan PC2 dikonfigurasi dengan alamat IPv4 pribadi, dengan R2 diaktifkan untuk PAT.

Proses PC ke Server

1. Gambar 1 menunjukkan PC1 dan PC2 masing-masing mengirimkan paket ke Svr1 dan Svr2. PC1 memiliki alamat IPv4 sumber 192.168.10.10 dan menggunakan port sumber TCP 1444. PC2 memiliki alamat IPv4 sumber 192.168.10.11 dan secara kebetulan diberi port sumber yang sama yaitu 1444.

2. Paket dari PC1 mencapai R2 terlebih dahulu. Menggunakan PAT, R2 mengubah alamat IPv4 sumber menjadi 209.165.200.225 (di dalam alamat global). Tidak ada perangkat lain di tabel NAT yang menggunakan port 1444, jadi PAT mempertahankan nomor port yang sama. Paket tersebut kemudian diteruskan menuju Svr1 di 209.165.201.1.

3. Selanjutnya paket dari PC2 sampai di R2. PAT dikonfigurasi untuk menggunakan satu alamat IPv4 global untuk semua terjemahan, 209.165.200.225. Mirip dengan proses penerjemahan untuk PC1, PAT mengubah alamat IPv4 sumber PC2 menjadi alamat global dalam 209.165.200.225. Namun, PC2 memiliki nomor port sumber yang sama dengan entri PAT saat ini, terjemahan untuk PC1. PAT menambah nomor port sumber hingga menjadi nilai unik dalam tabelnya. Dalam hal ini, entri port sumber dalam tabel NAT dan paket untuk PC2 menerima 1445.

Meskipun PC1 dan PC2 menggunakan alamat terjemahan yang sama, alamat global dalam 209.165.200.225, dan nomor port sumber yang sama yaitu 1444; nomor port yang dimodifikasi untuk PC2 (1445) membuat setiap entri dalam tabel NAT menjadi unik. Hal ini akan terlihat jelas pada paket yang dikirim dari server kembali ke klien.

Proses Server ke PC

4. Seperti yang ditunjukkan pada Gambar 2, dalam pertukaran klien-server pada umumnya, Svr1 dan Svr2 masing-masing merespons permintaan yang diterima dari PC1 dan PC2. Server menggunakan port sumber dari paket yang diterima sebagai port tujuan, dan alamat sumber sebagai alamat tujuan untuk lalu lintas kembali. Server tampak seperti berkomunikasi dengan host yang sama di 209.165.200.225; Namun, hal ini tidak terjadi.

5. Saat paket tiba, R2 mencari entri unik di tabel NAT menggunakan alamat tujuan dan port tujuan setiap paket. Dalam kasus paket dari Svr1, alamat IPv4 tujuan 209.165.200.225 memiliki beberapa entri tetapi hanya satu dengan port tujuan 1444. Dengan menggunakan entri dalam tabelnya, R2 mengubah alamat IPv4 tujuan paket menjadi 192.168.10.10, tanpa perlu mengubah port tujuan. Paket tersebut kemudian diteruskan menuju PC1.

6. Ketika paket dari Svr2 tiba, R2 melakukan terjemahan serupa. Alamat IPv4 tujuan 209.165.200.225 berada, sekali lagi dengan banyak entri. Namun, dengan menggunakan port tujuan 1445, R2 mampu mengidentifikasi entri terjemahan secara unik. Alamat IPv4 tujuan diubah menjadi 192.168.10.11. Dalam hal ini, port tujuan juga harus diubah kembali ke nilai aslinya yaitu 1444, yang disimpan dalam tabel NAT. Paket tersebut kemudian diteruskan menuju PC2.
