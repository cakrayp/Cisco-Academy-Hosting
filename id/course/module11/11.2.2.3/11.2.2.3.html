Konfigurasi NAT

Mengonfigurasi NAT Dinamis

Dengan menggunakan konfigurasi sebelumnya, gambar di bawah ini mengilustrasikan proses penerjemahan NAT dinamis antara dua klien dan server web:

Pada Gambar 1, arus lalu lintas dari dalam ke luar ditunjukkan:

1. Host dengan alamat sumber IPv4 (192.168.10.10 (PC1) dan 192.168.11.10 (PC2)) mengirimkan paket yang meminta koneksi ke server di alamat IPv4 publik (209.165.200.254).

2. R2 menerima paket pertama dari host 192.168.10.10. Karena paket ini diterima pada antarmuka yang dikonfigurasi sebagai antarmuka NAT di dalam, R2 memeriksa konfigurasi NAT untuk menentukan apakah paket ini harus diterjemahkan. ACL mengizinkan paket ini, jadi R2 akan menerjemahkan paket tersebut. R2 memeriksa tabel NAT-nya. Karena tidak ada entri terjemahan untuk alamat IP ini, R2 menentukan bahwa alamat sumber 192.168.10.10 harus diterjemahkan secara dinamis. R2 memilih alamat global yang tersedia dari kumpulan alamat dinamis dan membuat entri terjemahan, 209.165.200.226. Alamat IPv4 sumber asli (192.168.10.10) adalah alamat lokal di dalam dan alamat yang diterjemahkan adalah alamat global di dalam (209.165.200.226) di tabel NAT.

Untuk host kedua, 192.168.11.10, R2 mengulangi prosedur, memilih alamat global berikutnya yang tersedia dari kumpulan alamat dinamis, dan membuat entri terjemahan kedua, 209.165.200.227.

3. R2 menggantikan alamat sumber lokal dalam PC1, 192.168.10.10, dengan alamat global dalam yang diterjemahkan 209.165.200.226 dan meneruskan paket. Proses yang sama terjadi untuk paket dari PC2 menggunakan alamat terjemahan untuk PC2 (209.165.200.227).

Pada Gambar 2 diperlihatkan arus lalu lintas dari luar ke dalam:

4. Server menerima paket dari PC1 dan merespons menggunakan alamat tujuan IPv4 209.165.200.226. Ketika server menerima paket kedua, server merespons ke PC2 menggunakan alamat tujuan IPv4 209.165.200.227.

5a. Ketika R2 menerima paket dengan alamat IPv4 tujuan 209.165.200.226; itu melakukan pencarian tabel NAT. Dengan menggunakan pemetaan dari tabel, R2 menerjemahkan alamat tersebut kembali ke alamat lokal di dalam (192.168.10.10) dan meneruskan paket ke PC1.

5b. Ketika R2 menerima paket dengan alamat IPv4 tujuan 209.165.200.227; itu melakukan pencarian tabel NAT. Dengan menggunakan pemetaan dari tabel, R2 menerjemahkan alamat tersebut kembali ke alamat lokal di dalam (192.168.11.10) dan meneruskan paket ke PC2.

6. PC1 di 192.168.10.10 dan PC2 di 192.168.11.10 menerima paket dan melanjutkan percakapan. Router melakukan Langkah 2 hingga 5 untuk setiap paket. (Langkah 6 tidak ditampilkan pada gambar.)
