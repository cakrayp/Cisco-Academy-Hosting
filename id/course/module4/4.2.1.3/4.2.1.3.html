Keputusan Perutean

Peralihan Paket Antar Jaringan

Proses berikut terjadi ketika R1 menerima frame Ethernet dari PC1:

1. R1 memeriksa alamat MAC tujuan, yang cocok dengan alamat MAC antarmuka penerima, FastEthernet 0/0. Oleh karena itu, R1 menyalin frame ke dalam buffernya.

2. R1 mengidentifikasi bidang Tipe Ethernet sebagai 0x800, yang berarti frame Ethernet berisi paket IPv4 di bagian data frame.

3. R1 mendeenkapsulasi frame Ethernet.

4. Karena alamat IPv4 tujuan paket tidak cocok dengan jaringan mana pun yang terhubung langsung di R1, R1 menggunakan tabel peruteannya untuk merutekan paket ini. R1 mencari tabel perutean untuk alamat jaringan yang akan menyertakan alamat IPv4 tujuan paket sebagai alamat host dalam jaringan itu. Dalam contoh ini, tabel routing memiliki rute untuk jaringan 192.168.4.0/24. Alamat IPv4 tujuan paket adalah 192.168.4.10, yang merupakan alamat host IPv4 di jaringan tersebut.

Rute yang ditemukan R1 ke jaringan 192.168.4.0/24 memiliki alamat IPv4 hop berikutnya 192.168.2.2 dan antarmuka keluar FastEthernet 0/1. Ini berarti paket IPv4 dienkapsulasi dalam frame Ethernet baru dengan alamat MAC tujuan dari alamat IPv4 router hop berikutnya.

Karena antarmuka keluar berada pada jaringan Ethernet, R1 harus menyelesaikan alamat IPv4 hop berikutnya dengan alamat MAC tujuan menggunakan ARP:

1. R1 mencari alamat IPv4 hop berikutnya 192.168.2.2 di cache ARP-nya. Jika entri tersebut tidak ada dalam cache ARP, R1 akan mengirimkan permintaan ARP dari antarmuka FastEthernet 0/1 dan R2 akan mengirimkan kembali balasan ARP. R1 kemudian akan memperbarui cache ARP-nya dengan entri untuk 192.168.2.2 dan alamat MAC yang terkait.

2. Paket IPv4 sekarang dienkapsulasi ke dalam frame Ethernet baru dan meneruskan antarmuka FastEthernet 0/1 dari R1.
