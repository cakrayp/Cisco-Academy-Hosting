Switch Keamanan: Manajemen dan Implementasi

Ganti Keamanan Port

Pengintaian DHCP adalah fitur Cisco Catalyst yang menentukan port switch mana yang dapat merespons permintaan DHCP. Port diidentifikasi sebagai tepercaya dan tidak tepercaya. Port tepercaya dapat menjadi sumber semua pesan DHCP; port yang tidak tepercaya hanya dapat menyediakan permintaan sumber. Port tepercaya menghosting server DHCP atau dapat menjadi uplink ke server DHCP. Jika perangkat jahat pada port yang tidak tepercaya mencoba mengirim paket respons DHCP ke jaringan, port tersebut akan dimatikan. Fitur ini dapat digabungkan dengan opsi DHCP di mana informasi switch, seperti ID port permintaan DHCP, dapat dimasukkan ke dalam paket permintaan DHCP.

Seperti yang ditunjukkan pada Gambar 1 dan 2, port tidak tepercaya adalah port yang tidak dikonfigurasi secara eksplisit sebagai port tepercaya. Tabel pengikatan DHCP dibuat untuk port yang tidak tepercaya. Setiap entri berisi alamat MAC klien, alamat IP, waktu sewa, jenis pengikatan, nomor VLAN, dan ID port yang dicatat saat klien membuat permintaan DHCP. Tabel tersebut kemudian digunakan untuk memfilter lalu lintas DHCP berikutnya. Dari perspektif pengintaian DHCP, port akses yang tidak tepercaya tidak boleh mengirimkan respons server DHCP apa pun.

Langkah-langkah ini menggambarkan cara mengkonfigurasi pengintaian DHCP pada sakelar Catalyst 2960:

Langkah 1.Aktifkan pengintaian DHCP menggunakanip dhcp mengintipperintah mode konfigurasi global.

Langkah 2.Aktifkan pengintaian DHCP untuk VLAN tertentu menggunakanip dhcp mengintip vlannomormemerintah.

Langkah 3.Tentukan port sebagai tepercaya di tingkat antarmuka dengan mendefinisikan port tepercaya menggunakanip dhcp mengintip kepercayaanmemerintah.

Langkah 4.(Opsional) Batasi kecepatan penyerang dapat terus mengirimkan permintaan DHCP palsu melalui port tidak tepercaya ke server DHCP menggunakantingkat batas pengintaian ip dhcpkecepatanmemerintah.
