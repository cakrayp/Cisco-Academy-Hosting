Protokol Konfigurasi Host Dinamis v6

SLAAC dan DHCPv6

Seperti yang ditunjukkan pada Gambar 1, DHCPv6 stateless atau stateful, atau keduanya dimulai dengan pesan ICMPv6 RA dari router. Pesan RA mungkin berupa pesan berkala atau diminta oleh perangkat menggunakan pesan RS.

Jika DHCPv6 stateless atau stateful ditunjukkan dalam pesan RA, maka perangkat akan memulai komunikasi klien/server DHCPv6.

Komunikasi DHCPv6

Ketika DHCPv6 stateless atau DHCPv6 stateful ditunjukkan oleh RA, operasi DHCPv6 dipanggil. Pesan DHCPv6 dikirim melalui UDP. Pesan DHCPv6 dari server ke klien menggunakan port tujuan UDP 546. Klien mengirimkan pesan DHCPv6 ke server menggunakan port tujuan UDP 547.

Klien, yang sekarang menjadi klien DHCPv6, perlu mencari server DHCPv6. Pada Gambar 2, klien mengirimkan pesan DHCPv6 SOLICIT ke alamat server semua-DHCPv6 multicast IPv6 yang dicadangkan FF02::1:2. Alamat multicast ini memiliki cakupan link-local, yang berarti router tidak meneruskan pesan ke jaringan lain.

Satu atau lebih server DHCPv6 merespons dengan pesan DHCPv6 ADVERTISE seperti yang ditunjukkan pada Gambar 3. Pesan ADVERTISE menginformasikan klien DHCPv6 bahwa server tersedia untuk layanan DHCPv6.

Pada Gambar 4, klien merespons dengan pesan DHCPv6 REQUEST atau INFORMATION-REQUEST ke server, bergantung pada apakah server menggunakan DHCPv6 stateful atau stateless.

  • Klien DHCPv6 tanpa kewarganegaraan- Klien mengirimkan pesan PERMINTAAN INFORMASI DHCPv6 ke server DHCPv6 yang hanya meminta parameter konfigurasi, seperti alamat server DNS. Klien menghasilkan alamat IPv6 sendiri menggunakan awalan dari pesan RA dan ID Antarmuka yang dibuat sendiri.

  • Klien DHCPv6 berstatus- Klien mengirimkan pesan PERMINTAAN DHCPv6 ke server untuk mendapatkan alamat IPv6 dan semua parameter konfigurasi lainnya dari server.

Server mengirimkan BALASAN DHCPv6 ke klien yang berisi informasi yang diminta dalam pesan REQUEST atau INFORMATION-REQUEST seperti yang ditunjukkan pada Gambar 5.
