Ringkasan

Semua node di jaringan memerlukan alamat IP unik untuk berkomunikasi dengan perangkat lain. Penugasan statis informasi pengalamatan IP pada jaringan besar menghasilkan beban administratif yang dapat dihilangkan dengan menggunakan DHCPv4 atau DHCPv6 untuk menetapkan informasi pengalamatan IPv4 dan IPv6 secara dinamis.

DHCPv4 mencakup tiga mekanisme alokasi alamat yang berbeda untuk memberikan fleksibilitas saat menetapkan alamat IP:

  • Alokasi Manual- Administrator memberikan alamat IPv4 yang telah dialokasikan sebelumnya kepada klien, dan DHCPv4 hanya mengkomunikasikan alamat IPv4 ke perangkat.

  • Alokasi Otomatis- DHCPv4 secara otomatis memberikan alamat IPv4 statis secara permanen ke perangkat, memilihnya dari kumpulan alamat yang tersedia. Tidak ada sewa dan alamat ditetapkan secara permanen ke perangkat.

  • Alokasi Dinamis- DHCPv4 secara dinamis menetapkan, atau menyewakan, alamat IPv4 dari kumpulan alamat untuk jangka waktu terbatas seperti yang dikonfigurasi di server, atau hingga klien tidak lagi memerlukan alamat tersebut.

Alokasi dinamis adalah mekanisme DHCPv4 yang paling umum digunakan dan melibatkan pertukaran beberapa paket berbeda antara server DHCPv4 dan klien DHCPv4 yang menghasilkan penyewaan informasi pengalamatan yang valid untuk jangka waktu yang telah ditentukan.

Pesan yang berasal dari klien (DHCPDISCOVER, DHCPREQUEST) disiarkan untuk memungkinkan semua server DHCPv4 di jaringan mendengar permintaan klien, dan penerimaan, informasi pengalamatan. Pesan yang berasal dari server DHCPv4 (DHCPOFFER, DHCPACK) dikirim sebagai unicast langsung ke klien yang meminta informasi.

Ada dua metode yang tersedia untuk konfigurasi dinamis alamat unicast global IPv6.

  • Konfigurasi Otomatis Alamat Tanpa Status (SLAAC )

  • Protokol Konfigurasi Host Dinamis untuk IPv6 (Stateful DHCPv6)

Dengan konfigurasi otomatis stateless, klien menggunakan informasi yang disediakan oleh pesan IPv6 RA untuk secara otomatis memilih dan mengonfigurasi alamat IPv6 unik. Opsi DHCPv6 stateless memberi tahu klien untuk menggunakan informasi dalam pesan RA untuk pengalamatan, namun parameter konfigurasi tambahan tersedia dari server DHCPv6.

DHCPv6 berstatus mirip dengan DHCPv4. Dalam hal ini, pesan RA memberitahu klien untuk tidak menggunakan informasi dalam pesan RA. Semua informasi pengalamatan dan informasi konfigurasi diperoleh dari server DHCPv6 stateful. Server DHCPv6 menyimpan informasi status IPv6 serupa dengan server DHCPv4 yang mengalokasikan alamat untuk IPv4.

Jika server DHCP terletak di segmen jaringan yang berbeda dari klien DHCP, maka agen relai perlu dikonfigurasi. Agen relai meneruskan pesan siaran tertentu yang berasal dari segmen LAN ke server tertentu yang terletak di segmen LAN berbeda (dalam hal ini, pesan siaran DHCP akan diteruskan ke server DHCP).

Pemecahan masalah dengan DHCPv4 dan DHCPv6, melibatkan tugas yang sama:

  • Selesaikan Konflik Alamat

  • Verifikasi Konektivitas Fisik

  • Uji Konektivitas menggunakan Alamat IP Statis

  • Verifikasi Konfigurasi Switch Port

  • Uji Operasi pada Subnet atau VLAN yang Sama
