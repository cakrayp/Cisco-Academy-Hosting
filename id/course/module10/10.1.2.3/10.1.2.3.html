Protokol Konfigurasi Host Dinamis v4

Mengonfigurasi Server DHCPv4 Dasar

Apa itu Relai DHCP?

Dalam jaringan hierarki yang kompleks, server perusahaan biasanya berlokasi di server farm. Server ini mungkin menyediakan layanan DHCP, DNS, TFTP, dan FTP untuk jaringan. Klien jaringan biasanya tidak berada pada subnet yang sama dengan server tersebut. Untuk menemukan server dan menerima layanan, klien sering menggunakan pesan siaran.

Pada Gambar 1, PC1 mencoba memperoleh alamat IPv4 dari server DHCP menggunakan pesan siaran. Dalam skenario ini, router R1 tidak dikonfigurasi sebagai server DHCPv4 dan tidak meneruskan siaran. Karena server DHCPv4 terletak di jaringan yang berbeda, PC1 tidak dapat menerima alamat IP menggunakan DHCP.

Pada Gambar 2, PC1 sedang mencoba memperbarui alamat IPv4-nya. Untuk melakukannya, ituipconfig /rilisperintah dikeluarkan. Perhatikan bahwa alamat IPv4 dilepaskan dan alamatnya ditampilkan 0.0.0.0. Selanjutnya,ipconfig /perbaruiperintah dikeluarkan. Perintah ini menyebabkan PC1 menyiarkan pesan DHCPDISCOVER. Outputnya menunjukkan bahwa PC1 tidak dapat menemukan server DHCPv4. Karena router tidak meneruskan siaran, permintaan tidak berhasil.

Sebagai solusi terhadap masalah ini, administrator dapat menambahkan server DHCPv4 di semua subnet. Namun, menjalankan layanan ini di beberapa komputer menimbulkan biaya tambahan dan overhead administratif.

Solusi yang lebih baik adalah dengan mengkonfigurasi alamat pembantu Cisco IOS. Solusi ini memungkinkan router meneruskan siaran DHCPv4 ke server DHCPv4. Ketika router meneruskan permintaan penetapan alamat/parameter, ia bertindak sebagai agen relai DHCPv4. Dalam contoh topologi, PC1 akan menyiarkan permintaan untuk mencari server DHCPv4. Jika R1 dikonfigurasi sebagai agen relai DHCPv4, R1 akan meneruskan permintaan ke server DHCPv4 yang terletak di subnet 192.168.11.0.

Seperti yang ditunjukkan pada Gambar 3, antarmuka pada R1 yang menerima siaran dikonfigurasi denganip alamat pembantuperintah mode konfigurasi antarmuka. Alamat server DHCPv4 dikonfigurasi sebagai satu-satunya parameter.

Ketika R1 telah dikonfigurasi sebagai agen relai DHCPv4, ia menerima permintaan siaran untuk layanan DHCPv4 dan kemudian meneruskan permintaan tersebut sebagai unicast ke alamat IPv4 192.168.11.6. Itutampilkan antarmuka ipperintah digunakan untuk memverifikasi konfigurasi.

Seperti yang ditunjukkan pada Gambar 4, PC1 sekarang dapat memperoleh alamat IPv4 dari server DHCPv4.

DHCPv4 bukan satu-satunya layanan yang dapat dikonfigurasikan oleh router untuk diteruskan. Secara default,ip alamat pembantuperintah meneruskan delapan layanan UDP berikut:

  • Pelabuhan 37: Waktu

  • Pelabuhan 49: TACACS

  • Pelabuhan 53: DNS

  • Port 67: Klien DHCP/BOOTP

  • Pelabuhan 68: Server DHCP/BOOTP

  • Pelabuhan 69: TFTP

  • Port 137: Layanan nama NetBIOS

  • Port 138: Layanan datagram NetBIOS

Dengan menggunakan Pemeriksa Sintaks pada Gambar 5, konfigurasikan perintah relai DHCPv4 pada router yang benar sehingga PC3 dapat menerima informasi pengalamatan IPv4 dari server DHCPv4. Lihat kembali Gambar 1 untuk melihat topologi jaringan.
