Protokol Konfigurasi Host Dinamis v4

Operasi DHCPv4

Seperti yang ditunjukkan pada Gambar 1, DHCPv4 bekerja dalam mode klien/server. Ketika klien berkomunikasi dengan server DHCPv4, server memberikan atau menyewakan alamat IPv4 kepada klien tersebut. Klien terhubung ke jaringan dengan alamat IP yang disewakan hingga masa sewa berakhir. Klien harus menghubungi server DHCP secara berkala untuk memperpanjang sewa. Mekanisme sewa ini memastikan bahwa klien yang berpindah atau mematikan tidak menyimpan alamat yang tidak lagi mereka perlukan. Ketika masa sewa berakhir, server DHCP mengembalikan alamat ke kumpulan di mana alamat tersebut dapat dialokasikan kembali sesuai kebutuhan.

Asal Sewa

Ketika klien melakukan booting (atau ingin bergabung dengan jaringan), ia memulai proses empat langkah untuk mendapatkan sewa. Seperti yang ditunjukkan pada Gambar 2, klien memulai proses dengan pesan DHCPDISCOVER siaran dengan alamat MAC-nya sendiri untuk menemukan server DHCPv4 yang tersedia.

Penemuan DHCP (DHCPDISCOVER)

Pesan DHCPDISCOVER menemukan server DHCPv4 di jaringan. Karena klien tidak memiliki informasi IPv4 yang valid saat boot, klien menggunakan alamat siaran Layer 2 dan Layer 3 untuk berkomunikasi dengan server.

Penawaran DHCP (DHCPOFFER)

Ketika server DHCPv4 menerima pesan DHCPDISCOVER, server tersebut mencadangkan alamat IPv4 yang tersedia untuk disewakan kepada klien. Server juga membuat entri ARP yang terdiri dari alamat MAC klien yang meminta dan alamat IPv4 yang disewa dari klien. Seperti yang ditunjukkan pada Gambar 3, server DHCPv4 mengirimkan pesan DHCPOFFER yang mengikat ke klien yang meminta. Pesan DHCPOFFER dikirim sebagai unicast, menggunakan alamat MAC Layer 2 server sebagai alamat sumber dan alamat MAC Layer 2 klien sebagai tujuan.

Permintaan DHCP (DHCPREQUEST)

Ketika klien menerima DHCPOFFER dari server, ia mengirimkan kembali pesan DHCPREQUEST seperti yang ditunjukkan pada Gambar 4. Pesan ini digunakan untuk permulaan sewa dan pembaruan sewa. Ketika digunakan untuk asal sewa, DHCPREQUEST berfungsi sebagai pemberitahuan penerimaan yang mengikat ke server yang dipilih untuk parameter yang ditawarkan dan penolakan implisit ke server lain yang mungkin telah memberikan penawaran yang mengikat kepada klien.

Banyak jaringan perusahaan menggunakan beberapa server DHCPv4. Pesan DHCPREQUEST dikirim dalam bentuk siaran untuk menginformasikan server DHCPv4 ini dan server DHCPv4 lainnya tentang tawaran yang diterima.

Pengakuan DHCP (DHCPACK)

Saat menerima pesan DHCPREQUEST, server memverifikasi informasi sewa dengan ping ICMP ke alamat tersebut untuk memastikan alamat tersebut belum digunakan, membuat entri ARP baru untuk sewa klien, dan membalas dengan pesan DHCPACK unicast seperti yang ditunjukkan pada Gambar 5. Pesan DHCPACK adalah duplikat dari DHCPOFFER, kecuali untuk perubahan pada kolom jenis pesan. Ketika klien menerima pesan DHCPACK, klien mencatat informasi konfigurasi dan melakukan pencarian ARP untuk alamat yang ditetapkan. Jika tidak ada balasan ke ARP, klien mengetahui bahwa alamat IPv4 valid dan mulai menggunakannya sebagai miliknya.

Perpanjangan Sewa

Permintaan DHCP (DHCPREQUEST)

Seperti yang ditunjukkan pada Gambar 6, ketika masa sewa telah berakhir, klien mengirimkan pesan DHCPREQUEST langsung ke server DHCPv4 yang awalnya menawarkan alamat IPv4. Jika DHCPACK tidak diterima dalam jangka waktu tertentu, klien menyiarkan DHCPREQUEST lain sehingga salah satu server DHCPv4 lainnya dapat memperpanjang sewa.

Pengakuan DHCP (DHCPACK)

Saat menerima pesan DHCPREQUEST, server memverifikasi informasi sewa dengan mengembalikan DHCPACK, seperti yang ditunjukkan pada Gambar 7.
